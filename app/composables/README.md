# `app/composables` — باب الـ API الوحيد

> اقرأ [`PROJECT_GUIDE.md`](../../PROJECT_GUIDE.md) أولًا. هذا المجلد صغير لكنه **محوري**: كل حركة نحو الـ backend تمرّ من هنا.

## المسؤولية

`useApi()` هو **الباب الوحيد** للـ NestJS API (`D06-2`، `principle 12`). يوحّد: الأصل من البيئة، الـ bearer token من متجر الجلسة، إضافة `?locale=` على قراءات GET، شكل خطأ واحد (`RFC 7807`)، وإعادة محاولة تجديد صامتة واحدة عند 401.

## خريطة الملفّات

| الملف | الدور |
|---|---|
| `useApi.ts` | يبني عميل `$fetch` مُهيّأ ويُرجِع دالّة `apiFetch<T>` |
| `useSiteSettings.ts` | قراءة `GET /settings/site` مُشتركة، مُفتَّحة باللغة — يستهلكها البطل والتذييل، و`Nuxt` يُوحّد الطلب حسب المفتاح (بلا جلب مزدوج) |
| `useHomeData.ts` | بيانات أقسام الصفحة الرئيسية (`FR-PUB-011…016`): `useAsyncData` لكل قسم، بالتوازي، وكلٌّ يعزل خطأه فلا يُفرِّغ قسمٌ الصفحةَ (`NFR-DEGRADE`) |
| `useExperiences.ts` | قراءة `GET /experiences` (`FR-PUB-021`) بلغة المسار (`D06-6`)؛ يُرجِع المصفوفة بعد فكّ المغلّف — الترتيب وترتيب التقنيات ملك للـ API ولا يُعاد ترتيبهما |
| `useSiteSchema.ts` | بيانات `Person` + `WebSite` المنظَّمة للصفحة الرئيسية عبر `useSchemaOrg` من بيانات الـ API (`doc 22 §4`) — مصدر واحد للحقيقة |
| `usePreview.ts` | معاينة المسودّات عبر توكن (خارج نطاق الصفحة الرئيسية) |

## خريطة الاتصال

- **وارد:** كل صفحة/متجر يستدعي `useApi()`. أمثلة: `stores/auth.ts` (login/refresh/logout)، `pages/index.vue` (`/settings/site`)، `pages/blog/**` (`/articles`).
- **صادر:** `useRuntimeConfig` (الأصل)، `useAuthStore` (التوكن)، `useNuxtApp().$i18n` (اللغة الحالية)، ومساعد `requestWithRefreshRetry` من `utils/api-error.ts`.
- **يُنفَّذ الحظر:** أي `$fetch`/`useFetch` خام نحو الـ API خطأ ESLint (`no-restricted-syntax` في `eslint.config.mjs`، doc 15 §2)؛ `useApi.ts` هو الاستثناء الوحيد على مستوى الإعداد. أمّا المسارات الداخلية لـ `Nitro` (مثل `/api/prose` الذي يستدعيه `ContentProse`) فمُعفاة عبر `eslint-disable` سطري موجَّه يستشهد بالاستثناء — لأنها ليست الـ backend API بل بنية تحتية داخلية.

## التدفّق

```
useApi() → $fetch.create({ baseURL: apiBase, credentials: 'include', onRequest })
  onRequest:
    - GET؟ → options.query = { locale: $i18n.locale.value, ...query }   // قراءات مُوطَّنة (D10-6)
    - auth.accessToken موجود؟ → Header: Authorization: Bearer <token>
  apiFetch<T>(request, options):
    - isAuthRoute = request.startsWith('/auth/')   // لا نُجدِّد على مسار التجديد نفسه
    → requestWithRefreshRetry(() => client<T>(...), () => auth.refresh(), { retry: !isAuthRoute })
```

### شريحة المشاريع (005) واللغة الفعّالة (`D06-6`)

- **`useProjects.ts`** — ثلاث قراءات فوق `useApi()`: قائمة المشاريع (مفتاح يشمل اللغة والصفحة
  والمرشّح)، وتفصيل المشروع، وقائمة المهارات لمرشّح التقنيات. الترتيب ترتيب الـ API حرفيًّا
  (`D09-8`) — لا إعادة فرز في العميل.
- **`useSlugRedirect.ts`** — استعلام **واحد** لـ `GET /redirects/resolve` بعد 404 فقط (`D04-6`):
  `toPath` عند 200، و`null` عند 404 (جواب طبيعي لا فشل)، وأي حالة أخرى تُعاد رميًا — ابتلاع 5xx هنا
  يحوّل انقطاعًا مؤقّتًا إلى 404 يُزيل الصفحة من الفهرسة.
- **`useRouteLocale.ts` + `~/utils/route-locale.ts`** — **اللغة الفعّالة للقراءات العامّة تُشتقّ من
  المسار المقصود، لا من حالة الواجهة التفاعليّة** (`D06-6`).

**لماذا؟** انتقال `page-spread` (`D03-13`) يؤجّل تثبيت اللغة حتى يختفي الصفحة الخارجة، كي تنقلب
`<html lang dir>` ونصوص الواجهة في إطار واحد. لكن `setup()` للصفحة الداخلة يعمل **داخل** تلك النافذة،
فلو قرأ `useApi()` اللغة التفاعليّة لطلب **سلاگ الصفحة الجديدة باللغة القديمة** — وبما أنّ السلاگات
لكل لغة (`D04-2`) فهذا 404 مشروع لمحتوى موجود فعلًا. الحل: `useApi()` يقبل `locale` صريحًا، والقراءات
العامّة تُمرّر اللغة المشتقّة من المسار، **ونفس القيمة** تدخل مفتاح `useAsyncData` — مفتاح يسمّي لغة
والطلب يحمل أخرى يخزّن الحمولة الخاطئة تحت الاسم الصحيح.

`resolveRouteLocale` دالّة نقيّة تقرأ رموز اللغات المُهيّأة واللغة الافتراضيّة واستراتيجيّة
`prefix_except_default` — لا `en`/`ar` مكتوبة يدويًّا، فإضافة لغة لا تتطلّب تعديلها (`Pillar 3`).
لوحة التحكّم والمصادقة والطلبات غير القرائيّة **لم تتغيّر**.

### ملكيّة وسوم اللغة في الـ head (`D22-7`)

وحدة `@nuxtjs/i18n` — لا كود التطبيق — تملك كل وسم مشتقّ من اللغة: `<html lang dir>`، وبدائل اللغات
(`hreflang` مع `x-default`)، والرابط المعياري `canonical` المشتقّ من المسار، و`og:locale`
و`og:locale:alternate` و`og:url`، ومعاملات المسارات الديناميكيّة القادمة من `useSetI18nParams()`.
هذا يتم عبر الخيار الرسمي `i18n.experimental.strictSeo`، ولذلك **لا يُستدعى `useLocaleHead()`** — الوحدة
ترمي خطأً عليه في هذا الوضع، لأنّ وجود كاتبَين للوسم نفسه هو بالضبط سبب العطل `F-3`: بعد تبديل اللغة من
المتصفّح كانت `dir` تبقى `ltr` في صفحة عربية، و`canonical` يحمل السلاگ العربي على المسار الإنجليزي.

يبقى للصفحات والكيانات: العنوان، والوصف، وصورة `OG` للكيان، والبيانات المهيكلة، والوسوم العامّة
(`D22-6`). ويبقى `skipSettingLocaleOnNavigate` (`D03-13`) و`D06-6` كما هما — تغيّر **من يكتب** الوسوم،
لا **متى** تُثبَّت اللغة.

## قرارات جوهرية (شرح لمطوّر مبتدئ)

- **لماذا `$i18n` من `useNuxtApp()` لا `useI18n()`؟** لأن `useApi()` يُستدعى أيضًا **خارج** سياق setup (من إجراءات المتجر ومن الـ middleware)، حيث يرمي `useI18n()` خطأ `MUST_BE_CALL_SETUP_TOP`. الوصول عبر `$i18n` هو النمط الموثّق الآمن لهذا السياق (`principle 16`).
- **`credentials: 'include'`** يُرسِل كوكي التجديد؛ same-site في كل بيئة (`D19-3`)، فإرساله على القراءات العامّة غير ضارّ ويُبقي إعداد العميل واحدًا.
- **`credentials`/التوكن معًا:** التوكن في ترويسة `Authorization` (وصول)، والكوكي httpOnly (تجديد) — فصل مقصود (`D11-1`).
- **عزل أقسام الصفحة الرئيسية:** `useHomeData` يُنشئ `useAsyncData` مستقلًّا لكل قسم (بمفتاح يشمل اللغة) دون `await` تسلسلي، فتُجلَب بالتوازي؛ ويلتقط كلٌّ خطأه في `.error` بدل رفض الصفحة. `Nuxt` ينتظر كل وعود asyncData قبل تسلسل حمولة الـ SSR، فيبقى أول رسم مكتمل المحتوى (`doc 20 §2`, `doc 13 §2`).

## العقود والثوابت

- لا يُعيد `useApi` المحاولة على مسارات `/auth/*` (401 هناك = الجلسة انتهت فعلًا).
- الأنواع المُعادة تأتي من `~/types/models` (فوق العقد المولّد) — لا أشكال يدويّة.

## أخطاء شائعة

- استدعاء `$fetch`/`useFetch` للـ API مباشرةً — خطأ ESLint؛ استخدم `useApi()` داخل `useAsyncData`.
- استدعاء `useI18n()` داخل كود يعمل خارج setup — استخدم النمط القائم في `useApi`.
- **قراءة اللغة من `useI18n().locale` في قراءة محتوى عامّ** — استخدم `useRouteLocale()` (`D06-6`)،
  وإلّا انكسر تبديل اللغة على المسارات ذات السلاگ لكل لغة.
- **مفتاح `useAsyncData` بلغة تخالف اللغة المُرسَلة** — يجب أن تكون القيمة نفسها في الاثنين.
