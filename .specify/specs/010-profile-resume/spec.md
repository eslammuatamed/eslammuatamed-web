# Feature 010 — Profile Résumé Slice

**Umbrella:** `web-005 Profile Pages` (stays OPEN — Contact and the integrated Profile
closeout follow this slice).
**Routes:** `/resume`, `/ar/resume`.
**Requirements:** `FR-PUB-023`, `FR-PUB-024`.
**Contract source:** API `origin/dev` `188e771833024d9a52521a5cdaad936b38961b9b`.

## 1. Why this slice exists

`FR-PUB-023` requires a printable HTML résumé plus a downloadable PDF, one click from
public navigation. The header and mobile drawer have carried a `/resume` link since 007;
the route does not exist, so that link 404s today. This slice makes it resolve.

`FR-PUB-024` requires the HTML résumé to be sourced from the **same data as Experience and
Skills** — no second source of truth. That is the binding architectural constraint of this
slice and the thing most of its tests exist to defend.

## 2. Scope

**In:** bilingual HTML résumé at both routes; print layout; PDF download through the
existing public settings/media contract; an honest PDF-unavailable state; SEO, structured
data, accessibility, RTL, performance and test closeout.

**Out (explicitly):** generating or rewriting the PDF; PDF-from-structured-data generation
(a Future Consideration per doc 02 §"Media"); uploading a PDF to production; assigning a
production `resumeAssetId`; Contact; Prisma 7; `og:image`; promotion to `main`; deployment.

## 3. The PDF is an owner-maintained asset, never a source

The HTML résumé is composed from the API contract. It **must never** be generated by
parsing the PDF. The two are independent renderings of the same governed facts; the PDF is
a file the owner maintains and uploads, and the HTML is data-driven.

The canonical PDF is `content/cv/eslam-muatamed-cv-2026-08.pdf`
(SHA-256 `0958ec385c784b661175fbb38dfc7fec58bb3bdca3d14171990920f30f999283`), selected by
the owner on 2026-07-30; the 2026-07 file is superseded and non-canonical. Selecting,
governing and uploading it are **not** this slice's application work — the slice only has
to render whatever descriptor the contract serves, including `null`.

## 4. Data ownership (FR-PUB-024)

| Résumé region | Source | Rule |
|---|---|---|
| Name | `settings.siteName` | verbatim |
| Positioning line | `settings.tagline` | verbatim — the one governed public title (positioning-strategy v1.1.0); never re-authored |
| Email | `settings.professionalEmail` | the CV/outreach address; **never** `contactEmail`; omitted entirely when null |
| Links | `settings.profileLinks` | verbatim, API order |
| PDF | `settings.resumeAsset` | `PublicMediaPdfDescriptor \| null` |
| Experience | `GET /experiences` via the **same `useExperiences()` composable `/experience` uses** | API order, verbatim; never re-authored or summarized in Web |
| Skills | `GET /skills` | API `group` + `order`, verbatim |

Deliberately **absent**: About bio, engineering philosophy, current focus, projects,
testimonials, availability, address, phone number, admin/auth email, contact email,
`resumeAssetId`. None is required by FR-PUB-023/024, and each would either widen the page
past recruiter scanning or leak a non-résumé address.

Forbidden: invented proficiency percentages, years-per-skill, a résumé-only skills list,
or any hard-coded technology name the API already owns.

## 6. Structured data

`BreadcrumbList` only, plus the site-wide `Person` referenced by `@id`. **No second
`ProfilePage`** — D22-8 assigns `ProfilePage` to `/about` and names `/resume` explicitly:
"`/experience` and `/resume` do not duplicate the full ProfilePage identity unless a later
Web specification identifies a standards-supported need." This specification identifies
none. Schema.org has no résumé type; the standard WebPage/BreadcrumbList model is retained
rather than inventing one.

No `og:image` — finding F-1 (no branded social-image fallback) remains open, and emitting
a URL that does not resolve is worse than inheriting nothing.

## 7. Acceptance

- Both routes render in both locales, SSR-complete.
- Experience and Skills come from the shared reads; a test fails if a second content
  source appears.
- The PDF-null state is honest and the print action survives it.
- All doc 20 §1 budgets and thresholds hold **unchanged** for `/resume` and `/ar/resume`.
- Unfiltered axe clean across the full matrix.
- Owner approves the complete EN/AR copy inventory before merge (D16-8).
